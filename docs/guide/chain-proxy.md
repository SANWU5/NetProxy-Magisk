# 链式代理

链式代理把流量按「手机 → 当前节点（前置）→ 后置代理 → 目标网站」转发，对外出口是后置代理。
常见用法是用机场节点作为前置，经由它连接住宅或静态 IP 的 SOCKS5/HTTP 代理作为后置。

## 前置

前置默认跟随节点页的选择：在节点页切换节点或使用「自动最快」，链路的第一跳随之改变。
也可以在「链式」页的「当前链路」卡片中把前置固定为：

| 前置 | 行为 |
|---|---|
| 跟随节点页 | 默认值，与节点页的选择一致 |
| 节点分组的自动选择 | 在某个订阅或本地分组内自动选延迟最低的节点 |
| 智能分组或自建分组 | 使用该分组当前的选择，见[智能分组](./smart-groups) |
| 指定节点 | 固定使用某一个节点 |
| 在勾选的节点中自动选择 | 勾选几个节点，在它们之中自动选择；保存为自建分组「链式前置自选」 |

切换前置只切换选择器，不重载核心。固定的前置失效（例如节点被订阅删除、分组被删除）时，自动回退到跟随节点页。

## 链路测速

「当前链路」卡片分别显示前置节点和整条链路（前置 → 后置 → 目标）的延迟，连不上时显示「失败」或「超时」，
不会因为后置不可用而什么都不显示。切换前置或后置后会自动测一次，也可以手动点按测速。测速需要服务正在运行。

## 后置代理

在底栏「链式」页点按「导入后置代理」，每行一个代理，支持：

| 格式 | 示例 |
|---|---|
| 主机:端口 | `203.0.113.10:1080` |
| 主机:端口:用户名:密码 | `203.0.113.10:1080:user:pass`（密码可以包含冒号） |
| 用户名:密码@主机:端口 | `user:pass@proxy.example.com:3128` |
| SOCKS5 链接 | `socks5://user:pass@203.0.113.10:1080#住宅美国` |
| HTTP/HTTPS 链接 | `http://user:pass@203.0.113.10:8080`、`https://…` |
| 其他分享链接 | `vless://`、`trojan://`、`ss://` 等节点链接 |

没有协议头的行按导入面板中选择的协议（SOCKS5 或 HTTP）解析；IPv6 地址写成 `[2001:db8::1]:1080:user:pass`。
`#` 后面的文字作为名称，未写名称时使用「主机:端口」。相同协议、地址和账号的代理重复导入时会跳过。

点按后置代理可以测速、重命名或删除。测速经由当前前置完成，需要服务正在运行。
被手动模式或策略使用的后置代理不能直接删除，需要先切换手动后置或修改策略。

后置代理保存在模块的 `data/chain/landing.json`，设置与策略保存在 `data/chain/chain.json`，
升级时选择「保留现有数据」或「仅保留节点与订阅」都会保留。

## 后置模式

| 模式 | 行为 |
|---|---|
| 关闭 | 不经过后置，按节点页的选择出网 |
| 手动 | 所有走代理（Proxy）的流量都从「手动后置」出网 |
| 策略 | 只有策略中的应用从各自的后置出网，其余流量按节点页的选择出网 |
| 手动 + 策略 | 全部走手动后置，策略中的应用改走各自的后置 |

规则模式下直连的流量（国内网站、局域网等）不受影响；出站模式为 Direct 或 Wi-Fi 绕过生效时，策略中的应用同样直连。

## 应用策略

在「链式」页点按「新建策略」，填写名称、选择后置代理，并在应用列表中勾选要接管的应用（支持搜索）。
策略按包名匹配，对所有用户与应用分身生效；同一个应用只能出现在一个启用的策略中。
策略只在「策略」或「手动 + 策略」模式下生效，可以随时用开关临时停用。

应用自身的 DNS 查询仍由内核接管，不会被送进后置代理。

## 生效方式

服务运行时，修改模式、后置列表或策略会立即重载核心；只切换手动后置或前置时通过控制接口切换，不中断其他连接。
重载失败时自动恢复修改前的设置并提示原因。开启链式代理但没有可用后置时服务会拒绝启动，不会静默改为直连。

## 注意事项

- HTTP 后置不支持 UDP；需要 UDP 的应用（例如部分游戏、QUIC）请使用 SOCKS5 后置，并确认前置节点支持 UDP 转发。
- 后置代理的延迟包含前置的延迟，测速结果只反映当前前置。
- 旧版「策略」页（按 AI、谷歌、流媒体等分流到指定节点或地区）已移除。
